# Kairos design system

One source of truth for how Kairos looks on the web: the colours, type, spacing and components that kairos.io, the docs, the Kairos Installer, the Kairos console and hadron-linux.io share. The design is **Tessellate**, drawn in the decks of [kairos-io/design](https://github.com/kairos-io/design); this package is the same design as code, published as `@kairos-io/design` and documented here.

## Why

[kairos-io/kairos#5083](https://github.com/kairos-io/kairos/issues/5083) asked for a shared design system so that every Kairos web project draws from the same foundations instead of carrying its own slightly different copy. The decks settled what it looks like. The package makes it importable: the tokens as CSS custom properties and a Tailwind theme (#5511), React components with this Storybook (#5512), and a framework-free CSS layer for pages with no build step.

## One source

`packages/design/tokens.json` holds every value once. The decks read it, the stylesheets are generated from it, and a check in CI fails when a deck and the file disagree. So a colour in the Foundations deck, a swatch on these pages and a `bg-surface` in a component are the same number.

- **Foundations**: brand, colour, type, spacing, radius and elevation, theming, the tiles, icons.
- **Components**: every component in light and dark, with its accessibility checks run live.
- **Pages**: the screens from the decks, built from the components, so the decks and the package can be read side by side.
- **Adoption**: what each Kairos web project does to take the package.

## Where to go

- The decks: [kairos-io.github.io/design](https://kairos-io.github.io/design/). Foundations, the screens, Naming, the talk deck.
- Source: [github.com/kairos-io/design](https://github.com/kairos-io/design), `packages/design`. Issues go to [kairos-io/kairos](https://github.com/kairos-io/kairos/issues), like every Kairos repository.
- The tokens as data: `import { tokens } from "@kairos-io/design/tokens"`.
- Decisions: `packages/design/docs/adr/` explains the stack and why the package follows the decks.
