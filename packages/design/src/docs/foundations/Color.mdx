# Color

Two layers. The **brand palette** is the handful of fixed colours the artwork and the docs use. The **semantic tokens** are what components refer to: a role (`primary`, `muted-foreground`, `danger`) rather than a colour, with a value per theme. Switch the theme and every component follows, because nothing in a component names a colour.

## Brand palette

The oranges are the fills of the mark. The navy is the chrome of the docs site, the sidebar and the top bar. `tokens.css` exposes these as `--brand-*` and, for the docs site, under the `--kairos-*` names it already uses.

## Semantic tokens

Every swatch is live: switch the toolbar theme and it changes. The two values are light and dark.

## Status tones

Five tones carry every status in the system. `StatusBadge`, `StatusDot`, `Alert`, `Steps` and `StatTile` all take a tone, and `phaseTone()` maps a node, build or deployment phase string onto one so that "Online" is green on every screen.

<ToneRow />

A tone has two tokens. The solid value (`--success`) is for dots, bars and icons. The `-foreground` value is ink for text on the tone's 15% fill, which is how a badge or banner is drawn: `bg-success/15 text-success-foreground border-success/25`.

## Contrast

Computed from the token values, not promised. Normal text needs 4.5:1 for AA; large text and interface parts need 3:1.

<ContrastTable />

The muted text and the warning ink sit at the edge in one theme or the other. Use muted text for secondary lines, never for the only copy of a fact, and keep warning text at 13px or larger.
