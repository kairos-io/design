# Theming

## The pieces

```
src/tokens/index.ts      the source: typed objects, one value per token per theme
        │  scripts/build-tokens.ts
        ├── src/styles/tokens.css   :root (light), .dark / [data-theme=dark], and the OS-preference block
        └── src/styles/theme.css    @theme inline { --color-primary: var(--primary); ... } for Tailwind v4
```

Components never read a token directly. They use Tailwind utilities (`bg-primary`), which `theme.css` maps onto the custom properties that `tokens.css` sets. So:

- Changing a value is an edit to `src/tokens/index.ts`, a run of `npm run build:tokens`, and a diff on two generated files that CI checks are in step.
- Switching theme at runtime is a class on `<html>`. No rebuild, no JavaScript needed for the colours themselves.
- A page with no Tailwind uses the custom properties straight from `tokens.css`, as `components.css` does.

The generator writes the dark values twice, once under the class selector and once under the `prefers-color-scheme: dark` media query, and a test asserts the two blocks are equal. `useTheme` toggles both `light` and `dark` on `<html>`, so an explicit choice always beats the OS.

## Cascade layers

`styles.css` imports Tailwind's theme, preflight and utilities in named layers (`theme`, `base`, `utilities`). Layered styles lose to unlayered ones regardless of specificity, which is the property this system relies on: Docusaurus' Infima, the installer's layout CSS and any host stylesheet keep winning for the elements they already style. The package only takes over what nothing else claims.

## Adding a theme

A second theme is a third block of the same custom properties under a new selector, say `[data-theme="tessellate"]`. Add it to `src/tokens/index.ts` as another `Record<SemanticToken, string>`, teach the generator about it, and every component renders in it with no change of its own. The `noHardcodedColors` test is what makes this true: nothing in a component can bypass the tokens.

## Storybook

The toolbar theme switch sets the class on the preview `<html>`, so every story and every swatch in these pages can be checked in both themes. The accessibility addon runs on each story in whichever theme is active.
