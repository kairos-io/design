# Theming

## The pieces

```
packages/design/tokens.json     the source: brand, status, themes (light, dark), variants, type, space, radius, motion
        │  scripts/build.cjs
        ├── tokens.css          :root (light), [data-theme="dark"], the OS-preference block, the variants
        └── tailwind.css        @theme inline { --color-ink: var(--ink); ... } for Tailwind v4, no shadows, one radius
        │  scripts/check.cjs
        └── fails when a deck uses a colour or a name tokens.json does not have, or when the two files are stale
```

The same file feeds the design decks in this repository. Components never read a token directly: they use Tailwind utilities (`bg-surface`, `text-sub`), which `tailwind.css` maps onto the custom properties that `tokens.css` sets. So:

- Changing a value is an edit to `tokens.json`, a run of `npm run build`, and a diff on two generated files that CI checks are in step with the decks.
- Switching theme at runtime is an attribute on `<html>`. No rebuild, no JavaScript needed for the colours themselves.
- A page with no Tailwind uses the custom properties straight from `tokens.css`, as `components.css` does.
- The values as data are `import { tokens } from "@kairos-io/design/tokens"`, a typed view of the same JSON.

The attribute works on any element, so one section of a page can be dark on a light page. The generator writes the dark values twice, once under the attribute and once under the media query, and a test asserts the two agree. `useTheme`, `ThemeToggle` and `applyTheme` set the attribute for an explicit choice and remove it for "system", so an explicit choice always beats the OS.

## Variants

A few screens change a few values. `data-variant="hadron"` is the one most projects need: the Hadron blue accent, white ink on it, and the Hadron links. `console`, `site`, `installer` and `foundations` record the small differences the decks of those screens carry. Put `data-variant` on the element that carries `data-theme`, or below it. A variant never changes a component, only the values it reads.

## Cascade layers

`styles.css` imports Tailwind's theme, preflight and utilities in named layers (`theme`, `base`, `utilities`). Layered styles lose to unlayered ones regardless of specificity, which is the property this system relies on: Docusaurus' Infima, the installer's layout CSS and any host stylesheet keep winning for the elements they already style. The package only takes over what nothing else claims.

## Adding a value, a variant or a theme

A new token is a new name under `themes.light` and `themes.dark` in `tokens.json`. A new variant is a new entry under `variants` with the names it changes. A whole new theme is a third block of the same names; the generator and the check take it from there, and every component renders in it with no change of its own. The `noHardcodedColors` test is what makes this true: nothing in a component can bypass the tokens.

## Storybook

The toolbar theme switch sets `data-theme` on the preview `<html>`, so every story and every swatch in these pages can be checked in both themes. The accessibility addon runs on each story in whichever theme is active.
