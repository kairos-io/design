# Changelog

All notable changes to `@kairos-io/design`. The format is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/): a token value change or a prop removal is a major, a new token or component is a minor, a fix is a patch.

## [Unreleased]

### Added

- `Terminal` takes `lineNumbers`, the installer editor's gutter on every line: right-aligned numbers in the muted ink, Martian Mono at the terminal's size, sized to the largest number and never narrower than two digits, hidden from assistive technology and unselectable so the copy action and a manual selection take the text alone; a wrapped line keeps its number beside its first visual line, a streamed log keeps numbering as lines arrive, `firstLine` numbers a snippet from mid-file and `highlight` marks rows on the bar colour with the number in the key colour. `Textarea` takes `lineNumbers`, a gutter beside the control that counts the value's lines (controlled or typed) and follows its scroll to the last line, mono, with no soft wrap so each number sits beside exactly one line; the border, radius, focus and invalid state move to a wrapper around gutter and control, which stays a plain form control with its label and description. While focused, the caret's line (or every line a selection spans) shows its number in ink on a faint `raised` band across the row, as an editor does, and `highlight` marks a validator's lines in the danger tone. The vanilla layer has `.terminal.numbered` (an `<ol>` counted by CSS, with `--first-line`, `--gutter` and `.hl`) and `.textarea.numbered` (a bordered wrapper around a `.gutter` and a `<textarea wrap="off">`, with `.current`, `.error` and `.band` for the page to set).

- `TileBackground`, a full-bleed wireframe of Kairos cubes for a whole surface: the tile field's hexagons with no filled faces, every cell its three-rhombus outline, filling its positioned parent in the line token with a soft radial `vignette` (a number, a custom bias, or `false`), a seeded grain, and `depth`, which steps the outlines by row so the lower rows read as nearer. A proposal on top of the deck, and the one tile that may sit under copy. `cursor`, off by default, is a second proposal in three styles to compare, all opacity only on the grid's own points and resting at zero: `"lines"` brightens the outlines near the pointer in the accent (or the ink, `highlight="ink"`) and eases back over the slow duration; `"fill"` adds a faint wake of the three tones on the cube under the pointer; `"ripple"` runs one ring of brightness out from a press. The plumbing is `useCursorField` in `src/hooks` (Pointer Events on the parent or a `target`, one animation frame per move, no re-render, only with a fine hovering pointer and never under `prefers-reduced-motion`, nothing without `matchMedia`), which `TileField`'s cursor mode is to share once the loaders work lands; the geometry is `tileBackground` in `src/lib`. Stories under Components/Tiles/Backgrounds, with the real hero composed over the plane.
- Pages: the decks' screens built from the components, under "Pages" in the Storybook. The Kairos console (Fleet › Nodes, Fleet › Node detail, Factory › Build artifact), the kairos.io homepage, the Docs product page, the Kairos Installer's steps (real pages in an iframe from `tokens.css` and `components.css` alone) and the talk deck's layouts.
- Site components from the homepage and docs decks: `AnnouncementBar`, `SiteHeader`, `SiteFooter`, `Hero` (with the right-edge tile field, in either palette), `SiteSection` and `SectionHeading`, `FeatureGrid` and `FeatureCell`, `CommandSample`, `DocsNav` and `DocsToc`. The deep section and the footer nest `data-theme="dark"`, so they read the dark tokens in both page themes; the L1 / L2 / L3 track is `SegmentedControl` with `code`.
- `Slide` and the layouts of the talk deck (`SlideTitle`, `SlideSpeaker`, `SlideAgenda`, `SlideDivider`, `SlideStatement`, `SlideList`, `SlideTerminal`, `SlideCode`, `SlideLifecycle`, `SlideTable`, `SlideNumber`, `SlideImage`, `SlideScreenshot`, `SlideQuote`, `SlideDemo`, `SlideClosing`), a 1920×1080 frame scaled to its container, light mode only, with `brand="hadron"` for a Hadron talk.
- `HadronMark` and `HadronLogo`, the Hadron artwork from the decks under `assets/logos/hadron-*`, and `hadronLogoAssets`. The Kairos lockup gains a `dark` rendition (colour mark, white wordmark, the decks' dark-surface logo) and `logoAssets.horizontal.dark`.
- Foundations/Hadron: what the variant changes and keeps, the three blues, the contrast rule, the Hadron tiles, when a screen is Hadron, and the same components under both brands. Foundations/Naming: the Naming deck as a docs page.
- `applyBrand()`, `getBrand()` and the `Brand` type set and read `data-variant="hadron"` on `<html>`, the way `applyTheme` does `data-theme`; `resolveThemeTokens(mode, variant)` returns the token values an element under a theme and a variant reads.
- The Storybook toolbar has a Brand switch (Kairos, Hadron) beside the theme switch; the contrast table and the contrast tests cover every pair in both themes as Kairos and as Hadron, and a test fails the build when a component names a brand colour instead of the accent.
- Console components from the console decks: `Gauge`, `Sparkline` and `TileMeter`, the live meters of the node detail deck, with `gaugeTone()` and the 70 / 85 thresholds; `DescriptionList`, the two-column facts panel; `ChoiceCard` and `ChoiceGroup`, the wizard's selectable cards; `Switch`, the wizard's settings toggle; `FilterChip`, the status filters and pick lists; `WizardSteps`, the horizontal wizard rail. `SidebarItem` takes a `count` and its `icon` is optional; `StatTile` takes `size` ("lg" | "sm") and `mono` and draws a tone bar; `PageHeader` takes `mono` and `eyebrow`.
- `TileField` takes `animate="cursor"`, opt-in and a proposal on top of the deck: the `"in"` entrance, after which the cubes near the pointer light up (an empty cell with a faint fill of its tone, a filled cube a shade brighter), fade with distance and settle back over the slow duration once the pointer leaves. Opacity only, on a glow layer that rests at zero so the resting field is the static one; Pointer Events on the parent (or a `target` element, which `Hero` sets to the whole hero), one animation frame per move, no re-render; only on a device that can hover with a fine pointer and never under `prefers-reduced-motion`.
- `TileField` takes a family of entrances through `enter`, proposals on top of the deck for one to be picked, and `folded`, a controlled prop that runs the chosen entrance in reverse. `"fall"`: each cube falls from one hexagon height above (`--tile-fall`, from the radius) under gravity and settles with a 1.5px overshoot. `"assemble"`: the three faces arrive from their own sides and snap together at the centre vertex. `"unfold"`: the faces hinge open from that vertex onto their outlines, a scale toward the shared vertex along the face's own two edges. Every entrance staggers from the dense edge, moves by transform and opacity only, never scales a face beyond its cell, lands exactly on the outline over a complete grid, and comes off once landed, so the resting field is the static one; the face-wise ones offset the faces by a few tens of milliseconds in tone order. `folded` leaves sparse edge first, dense edge last, down to the grid alone, and enters again when it flips back; under `prefers-reduced-motion` the cubes appear and disappear with no motion. `tileFaceMotion`, `tileFoldDelay` and `tileDelaySpan` sit beside `tileEnterDelay` in `src/lib/tiles.ts`. Stories "Entrances, side by side", "Falls into place", "Unfolds into place" and "Folds away".
- Loading built from the tile motion, three opt-in proposals on top of the deck, all over an outline grid that never leaves and all still under `prefers-reduced-motion`; `enter="assemble"` (default) or `"unfold"` on each. `TileLoader`: one cube at 16, 20 or 24px whose faces come into place in tone order, rest, come apart and return (`tone="mono"` paints them in `currentColor` at three strengths for a fill), an image named "Loading" unless `decorative`, in a box padded so no stroke or moving face is clipped. `TileBar` takes `current` (`true` for the tile at `done`, or an index) to loop the motion on the step in progress, brings each tile into place once as it becomes done, and is indeterminate with `current` and no `done`, the loop travelling the bar as a wave. `TileRing`: the Kairos mark itself, its eighteen rhombi read from the icon's artwork (`kairosMarkTiles`, `quadMotion` and `tileRingFrame` in `src/lib/mark.ts`) and kept turned as the mark turns them, with `mode="build"` (default: cubes in one by one clockwise from the top, a beat as the mark, out one by one) or `"chase"`. The cycles (`.tile-loop-*`, `.tile-chase-*`, `.tile-build-*`, `.tile-step-*` in `base.css`) lay each entrance and its reversal end to end, every duration a multiple of `--tile-enter-duration`; unfolding scales each face in the exact frame of its own two edges from inline per-face values, so any rhombus hinges on its true vertex. `Button loading` shows `TileLoader` over the label instead of the Lucide spinner, the label kept in place and transparent so the button's width never changes. `TileBar` lives in its own file; `done` is optional when `current` is set. Each loader takes `status` (`"loading" | "success" | "error"`) and `onSettled`: the loop runs to its next quiet moment, then lands once more in the status tones over the brand faces and rests (the bar crossfades its done tiles, the ring builds a final lap), the name turns to "Done" or "Failed" with a polite live region, and under reduced motion the tiles simply turn. The tiles' status tones are new tokens, `color.tile` in `tokens.json` (`--tile-success-light/-mid/-deep` from the healthy green, `--tile-error-*` from the recovery red), and `tilePalettes` gains `success` and `error`. The hairline grid of `TileField`, the loaders and the pattern files is drawn as unique lattice edges (`tileGridPaths`), each once at the stronger of its two cells' strengths, batched by opacity with round caps, and every filled face carries the one face stroke (`tileFaceStroke`: 0.6 units, bevelled, under the fill, the top face of a cube drawn last), so no shared edge is darker than another, no vertex is a knot and no corner grows a pin. Stories under Components/Tiles/Loaders, including a build queue of nine cards.
- `TileField` takes `idle="wave"`, a proposal on top of the deck: one slow band rolls across the whole field from the dense edge to the sparse one along the fade (right to left on the default hero, outward from a centred field; a custom bias runs from its denser side), each cube lifting 1.5px and dimming for a moment, then a gap before it comes round again, for a working state (a build, an install) where `"live"` is for a screen left open. CSS only: `.tile-wave` in `base.css` with the period `calc(var(--duration-slow) * 20)` (`--tile-wave-period`) and each cube's delay a share of it from `tileWavePhase` and `tileWaveAxis` in `src/lib/tiles.ts`, opacity and translate only, never a scale; only once the entrance has landed, never while folded, and no class at all under `prefers-reduced-motion`. Stories "Wave across the field" and "Working state".
- `phaseLook()` maps a phase to the deck's five status looks (Healthy filled green, Upgrading filled accent, Recovery filled red, Installing accent outline, Offline muted outline); `toneFill` and `toneStroke`. `CardLabel` and `CardValue` for the deck's stat tile. `inputClasses` is exported.

### Changed

- `THEME_ATTRIBUTE` (`"data-theme"`) is exported beside `BRAND_ATTRIBUTE`, so a host can read or watch the attribute `applyTheme` sets without spelling it.
- `TableRow` shows the 2px ink focus ring, inset, when a host makes a row focusable, and the selected row's accent bar is an inset shadow in the same layer, so a focused selected row shows both. The Nodes page makes each node's name a button in its first cell (Tab reaches it, Enter and Space pick the node, the row lights with the ring) and the row itself is no longer a tab stop; the Docs product page stacks the navigation above the article on a phone.
- `CommandSample` shows a copy icon on its chip and, once copied, the chip takes the filled success look (healthy green, status ink) with a check beside "Copied" for a moment, as does the `Terminal` copy action; the chip keeps the width of its copied state so the row never shifts. Copying works on a plain http page too (`copyText` in `src/lib/clipboard.ts` falls back to the legacy command where there is no Clipboard API), and when nothing can copy the command's text is selected and the chip says "Selected" instead of claiming a copy; `Terminal` says "copied" only once the text is on the clipboard. `SegmentedControl` reserves the width of each option's bold label, so choosing an option in the own-widths layout no longer moves its neighbours.
- `TileField`'s motion is three props instead of one: `enter` ("drop" | "fall" | "assemble" | "unfold" | false) is the entrance, `idle` ("live" | "cursor" | false) what the field does once it has landed, `folded` whether the cubes are there at all. `animate` still works as a deprecated shorthand (`"in"` is `enter="drop"`, `"live"` and `"cursor"` add the matching `idle`) with an explicit prop winning, and goes before 1.0. The SVG carries `data-enter`, `data-idle` and `data-folded` instead of `data-animate`. `Hero`'s `tiles` passes the new props through.
- `SiteFooter` keeps the brand block on the left: the column layout sets `items-start`, so the logo keeps its own width instead of being stretched across the cell and centred by the SVG's `preserveAspectRatio`. The footer stories take the dark-surface lockup (`variant="dark"`: colour mark, white wordmark), as the decks and the page stories do, not the one-colour white rendition.
- `TileField` and the `tile-field-*.svg` patterns fade their outline grid with the bias: each cell's hairline takes the opacity of its weight relative to the field's densest cell (a filled face always keeps a full outline), so the sparse edge of a field dissolves instead of stopping in a hard line, as on the talk deck's section divider.
- `tokens.json` is in the W3C Design Tokens (DTCG) format: `$value` and `$type` on every token, groups, and `{path.to.token}` aliases that show where a theme colour comes from. `scripts/build.cjs` resolves it and writes `tokens.css`, `tailwind.css` and `src/tokens/resolved.json` (the typed view behind `@kairos-io/design/tokens`); the generated CSS is unchanged apart from the renames below and a new `--white`. See ADR 0004.
- The custom properties are kebab-case: `--accent-soft`, `--accent-line`, `--on-accent`, `--warn-bg`, `--code-bar`, `--code-key`, `--code-ink`, `--code-muted` (were camelCase). The Tailwind utilities did not change.
- The decks read `tokens.css`: every deck links `packages/design/tokens.css`, paints with `var(--token)` and switches theme with `data-theme` on its root instead of carrying a theme map. `check:tokens` fails a deck that does not, names a variable that does not exist, or sets a variant it may not use.
- The package moved into `kairos-io/design` as `packages/design`, next to the design decks, and merged with the tokens package that landed there (kairos-io/kairos#5511). `tokens.json` is now the only token source; `src/tokens/index.ts` is a typed view of it. The generator and the deck check are the repository's, extended with the status warning amber and the ink on a status fill, the terminal inks (`code-ink`, `code-muted`), the dialog scrim (`overlay`), the 2 / 4 / 8 / full radius steps and the motion tokens. See ADR 0003.
- The design is the decks' (Tessellate). Urbanist and Martian Mono replace Noto Sans and ship self-hosted under `assets/fonts`, loaded by `fonts.css`; one violet neutral family replaces the slate and navy set; the radius is 4px with 2px for tags and 8px for dialogs; there are no shadows and the Tailwind `shadow-*` utilities are removed; ink on the accent is dark on Kairos orange and white on Hadron blue; links are `--link`.
- Components use the decks' token names: `bg`, `side`, `surface`, `inner`, `head`, `hover`, `raised`, `line`, `ink`, `sub`, `muted`, `accent`, `accent-soft`, `accent-line`, `on-accent`, `link`, `ok`, `warn-bg`, `deep`, `code`, `code-bar`, `code-key`. The AuroraBoot names (`background`, `card`, `muted-foreground`, `primary`, `sidebar-*`, `terminal-*`) are gone; the Adoption page lists the renames.
- The theme is `data-theme="light|dark"` on `<html>` (or any element), as the decks use it. `applyTheme`, `useTheme`, `ThemeToggle` and `inlineThemeScript()` set the attribute; the `light` and `dark` classes are no longer read.
- Hadron is `data-variant="hadron"`: the blue accent with white ink and the Hadron links in either theme. The tiles keep `palette="hadron"`.
- The Tailwind entry is `@kairos-io/design/tailwind.css` (it imports `tokens.css`); `theme.css` is gone. `tokens.css`, `tailwind.css` and `tokens.json` are exported from the package root as well as from `dist/`.
- The tones map onto the decks' status colours: success is `status-healthy` with `ok` ink, warning `status-warning`, danger `status-recovery`, info the accent with `link` ink, neutral `muted`. Badges and dots draw a diamond, as the decks do.
- The Storybook is published under `/storybook/` of the repository's Pages site, next to the decks, and the packed tarball under `/packages/design/` so a branch build can be installed with `npm install <url>`.
- Button follows the Foundations deck: the accent with dark ink (bold, 15px, 11×18 padding), a new `dark` variant (the ink button; `secondary` is its alias), a 1.5px ink `outline`, `link` in the link colour, `destructive` in the recovery red; focus is a 2px ink outline, disabled is the raised fill with muted ink. `on-navy` is deprecated (use `ghost`).
- Card has no border or shadow; `bordered` adds a hairline. Input, Textarea and the Select trigger share one look: a surface with a 1.5px hairline that turns to ink on focus and recovery red when invalid; `mono` sets Martian Mono at 13px for technical values.
- StatusDot is the deck's diamond (SVG), filled or `outline`d in its tone; StatusBadge is a surface chip with the diamond and ink text, never tinted, with `outline` and `bare`. `toneSoft` is deprecated.
- Badge is the deck's tag: mono 12px on the raised fill with a 2px radius, `outline` for a hairline, `accent` for a count; `default` is no longer the accent. Chip matches, with an `outline` prop.
- Tabs are a row on a hairline, 15px semibold, the active tab underlined in the accent line. SegmentedControl is the raised track with the chosen option on the surface; options take a mono `code` ("L1") and `fill` spreads them evenly.
- Terminal is the deck's code block: a bar with a `title` and an optional `copy` action, `prompt` lines with "$" in the key colour, `code-ink` and `code-muted` text. Alert is the deck's callout: a surface with a tone diamond, a bold lead in the same line and a link-coloured `action`; the default tone is `info`. Label is 14px semibold; InfoTooltip's panel is a surface with a 1.5px hairline and link-coloured links.
- `components.css` draws the decks: 16px body, links in `--link`, buttons at 15px/700 with the accent, ink, outline and link variants, 1.5px input borders with ink on focus, mono inputs, diamond checkboxes and radios, a `.toggle` switch, status as a diamond beside ink text on a surface chip, `.tag` chips in mono on raised with a 2px radius, callouts as a surface with a diamond in the margin, the step rail with tile markers, a `.tilebar` progress bar in the tile order, a `.terminal` and `.code.editor` on the code ground, a `.disk-layout` bar, a `.segmented` control, and the 2px ink focus ring. No shadows, no tinted fills.
- The sidebar, table, stat tile, steps, page header, dialog and empty state render as the console decks draw them: the side surface with mono section labels and an accent tile on the active item, a surface table with the head tone and an inset accent bar on the selected row, borderless stat tiles with a 34px value, diamonds for step markers, the 30px page title with "/" breadcrumbs in the link colour, an 8px dialog on the surface. Status is a diamond beside ink text everywhere.
- Foundations/Brand covers both marks, the lockup rules from the Naming deck and the "never" list from the Foundations deck; the logo generator reads every SVG shape tag, not only rect and path.

## [0.1.0] - 2026-10-09

The first cut: the design the Kairos web projects already ship, as one package.

### Added

- Tokens: brand palette, semantic colours for light and dark, the five status tones, the Noto Sans and monospace stacks, a type scale, the 4px spacing scale, breakpoints, layout measures, radius, shadows and motion. One TypeScript source (`src/tokens`), generated into `tokens.css` and a Tailwind v4 `theme.css`, with tests that both themes and the OS-preference block agree.
- React components: Alert, Badge, Button, Card, Checkbox, Chip, Dialog and ConfirmDialog, EmptyState, Field, InfoTooltip, Input, Label, Logo (KairosMark, KairosLogo), PageHeader, SegmentedControl, Select, Separator, Sidebar and AppShell, StatTile, StatusBadge, StatusDot, Steps, Table, Tabs, Terminal, Textarea, ThemeToggle, Toast. The `useTheme` hook, `inlineThemeScript()`, `cn()`, `phaseTone()` and the tone class maps.
- `components.css`: the web installer's component classes over the tokens, for pages with no build step.
- Storybook with every component in both themes, accessibility checks, and the Foundations, Getting started and Adoption pages. Published to GitHub Pages.
- Examples: a React + Vite consumer, a plain HTML page, and a Go binary that embeds the stylesheets. CI installs the packed tarball into the React example and builds it.
- Tiles: the mark's rhombi laid flat. A pure geometry library (`src/lib/tiles.ts`: `tileField`, `tileHexagon`, `tileFieldSvg`, the fade presets), five components (`TileField`, `TileUnit`, `Tile`, `TileBar`, `TileMarker`) and five static SVG fields under `assets/patterns/` for pages with no build step. The shapes come from the Tessellate direction in `kairos-io/design-system` (October 2026) and paint with the `--brand-*` tokens. The Hadron blues (`--brand-hadron-sky` #1BAAFF, `--brand-hadron-blue` #0275E7, `--brand-hadron-deep` #004CCE, exported as `hadron`) are the second brand set from the same source; every tile component takes `palette="hadron"` and the pattern files ship in both palettes.

### Changed

- The toast tones use the status tokens instead of Tailwind's green and red, a deliberate change from AuroraBoot's toaster.
- `applyTheme` sets both `light` and `dark` on `<html>`, so an explicit choice beats the OS preference now that `tokens.css` follows `prefers-color-scheme` when neither class is present.
- Ink on the orange accent (the active sidebar item, the current wizard step, the pressed theme button) is `--primary-foreground`: white in light, navy in dark, because white on the dark theme's soft orange is 2.68:1.
- `--destructive-foreground` is navy in the dark theme and the destructive button uses it, because white on the dark danger red is 2.99:1.
- `--muted-foreground` in the light theme is #5b6879 instead of #64748b, so muted text on the muted surface (inactive tabs) reaches 5.18:1 instead of 4.34:1.
- Sidebar section and rail labels use a new `--sidebar-fg-muted` token (6.0:1 on navy) instead of the sidebar ink at 40% opacity (3.2:1).
- The current wizard step's marker shows its number in navy on white rather than in the accent orange, which did not pass on white.
- One `--overlay` token (black at 60%, 70% in dark) scrims the dialog, the navigation drawer and the vanilla `.backdrop`, where AuroraBoot used 80% and 60%.
- Dialogs open with the system's own fade-up animation; the tailwindcss-animate classes AuroraBoot used had no effect without that plugin.
- Every focus ring is 2px (`--shadow-focus`); AuroraBoot's buttons and inputs had 1px.
- `Badge` renders a `<span>`, so it can sit inside headings and table cells.
- `SidebarSteps` takes the same `{ id, label, state }` items as `Steps`.

- `SegmentedControl`: the group's name is now passed as `aria-label` (was `ariaLabel`), matching Steps and Terminal.
- `EmptyState`: `text` is now `description`, matching PageHeader, Checkbox and ConfirmDialog.
- `PageHeader`: `renderLink` is gone; a breadcrumb item takes an optional `element` (the host's router link) instead.
- `InfoTooltip`: the panel is a labelled disclosure (`aria-expanded`, `aria-controls`, `role="group"`) rather than `role="tooltip"`; Escape closes it; new `label`, `className` and `defaultOpen` props.
- `Toast` type renamed `ToastMessage` (`Toast` remains as a deprecated alias); `useToastListener` is no longer exported from the package root.
- `useTheme` renders "system" on the server and on the first client render, then reads the stored mode, so Docusaurus no longer hydrates with a mismatch. Storage-blocked browsers keep the choice in memory.
- `EmptyState`, `PageHeader`, `StatTile`, `MeterBar`, `StackBar`, `Steps`, `SegmentedControl` and `InfoTooltip` forward refs and spread HTML attributes.
- `Field` sets the native `required` attribute as well as `aria-required`.
- Every control uses the same 2px focus ring; the vanilla layer's `--shadow-focus` matches.
- The shipped `styles.css` no longer includes utilities used only by stories and tests.
